# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Add durable project-specific notes here as they are discovered through real work.

## Sharp edges

- **Names are settled.** The binary is `tetanus`; the publishable umbrella crate is `tetanus-hardness`, because bare `tetanus` is squatted on crates.io. Do not rename either.
- **Upstream disagrees with itself about `system-prompt/assemble`.** `architecture.md` puts prompt assembly before `agent/pre-step`; `agent-lifecycle.md` names the event and puts it inside the step. tetanus follows agent-lifecycle.md. The reasoning is in `docs/turn-flow.md` section 6.1; read it before "fixing" the order.
- **Four dispatch modes, not five.** Upstream's low-level API doc lists a `bail` mode; the harness primer documents four to plugin authors, and Phase ① implements those four. `bail` is reachable through serial.
- **The merge gate is the conformance suite.** `MOCK_TURN_FLOW` in `crates/turn/tests/harness/mod.rs` is the whole expected event sequence, asserted by equality. Changing the driver's event order means changing that constant on purpose, in the same commit, with a reason.
- **Every test runs offline.** No case may need an API key. The one live provider case reports itself skipped when `DEEPSEEK_API_KEY` is absent. Keep it that way, or CI stops being a gate.
- **One tracer, two readers.** `TurnTrace` (`crates/turn/src/trace.rs`) feeds both `tetanus run` and the conformance suite, so the printed sequence and the asserted sequence cannot drift. Do not add a second observer.
- **The engine<->presentation boundary is published, not implied.** `docs/interface-contract.md` is the spec; `crates/protocol` is the same contract as Rust types. Any change to either lands as its own PR touching both plus the doc's changelog, never inside a feature PR. The doc's file-ownership table says which lane owns which path.
- **`docs/contract-updates/` is how one lane says something to another.** The boundary doc is edited in place and every lane collides there, so a change or a question is written as its own note in that directory and folded in later. A note is the right answer to "I need something another lane owns" - never reach across and build it. **A note is not a delivery.** It is invisible until the branch lands, so anything another lane should act on now - a security finding above all - goes into the status line the hour it is written, with the note as the detail. `ui-terminal-send-secrets.md` sat unread for an hour because that was done in the wrong order.
- **Phase boundaries.** Layered config recompose, deeper reversible effects, the full tool pipeline, more adapters, a subcommand that hosts the WebSocket carrier, and the WASM host are Phase ②/③. `docs/PLAN.md` is the captain-approved decision doc. The JSON-RPC codec and both its carriers are served: `crates/rpc`, stdio and WebSocket, conformance in `crates/rpc/tests/`.
- **Docs are part of done.** `README.md` has a truthful status table, `ARCHITECTURE.md` is the workspace design description, `CONTRIBUTING.md` holds the dev commands. A behaviour change that leaves them stale is unfinished; `CONTRIBUTING.md` states the standards they follow.
- **There are two gates, and the second one is `sentrux gate`.** It reads the committed `.sentrux/baseline.json` and prints an absolute quality score: hold 7000+, floor 6200, and quote it in the pull request body. It scans `git ls-files`, so an uncommitted or untracked change is invisible to it: a new crate measures identically to `master` until it is committed. Commit the slice, then gate it, or the number is about somebody else's tree. **Never `sentrux gate --save`** - that overwrites the thing the branch is being measured against, so a branch that saves reports "no degradation" by construction. Where code goes moves the number more than what it does: registering one tool family in `crates/cli/src/main.rs` cost 432 points for forty-five lines and nothing at all in `crates/cli/src/tools.rs`, which is why the binary's tool composition lives there. `CONTRIBUTING.md` has the reasoning and the other two things that move it; refreshing the baseline is its own PR naming the commit measured.
- **A journal-payload case that asserts an explicit `null` must use `get`.** `serde_json` indexing answers `Value::Null` for a key that is absent, so `data["x"] == Value::Null` also passes on a record that dropped `x` entirely - which is the defect such an assertion exists to catch. `crates/turn/tests/upstream_retry_executor.rs` (TC-PORT-RETRYX-1) carries the form and the reason. The distinction is load-bearing here because the interface contract spends it: §4.3.2 payloads carry `null` for a fact that does not apply, §4.5 error `data` omits the key.
- **A green test count is not proof the gate ran your code.** Confirm a case that exists only in your tree actually appears in the run. Every lane must also point `CARGO_TARGET_DIR` at its *own* directory: cargo does not hash the final binary, every lane writes `debug/tetanus`, and the CLI tests exec that exact path through `env!("CARGO_BIN_EXE_tetanus")`, so two lanes sharing one target directory can run each other's binary and still pass.
- **The terminal-backed cases fail under load and pass alone.** `crates/ui/tests/killed.rs` TC-UI-TERM-5 and `crates/exec/tests/upstream_terminal_session.rs` both wait on a child arming itself or a signal landing, and a workspace run competing with other lanes' builds loses those races; each passes on its own and TC-UI-TERM-5 fails the same way on bare `master`. Several lanes have each spent a round proving it was not theirs. Before chasing one, re-run that suite alone, and if it still fails, run it from a scratch worktree of `master` - `tetanus-ui` depends on no workspace crate, so that build is cheap and the answer is decisive.
- **`docs/parity-changelog.md` is append-only and merged, not adjudicated.** It is a separate file marked `merge=union` in `.gitattributes` because every slice in flight appends one row and git merges by line, which made a queue of four slices produce four identical conflicts per merge. Rows are historical facts: write one, never revise one - a correction is a new row saying what it corrects. Do not widen the pattern; union merge never reports a conflict, so `docs/parity.md` and `docs/interface-contract.md`, which are edited in place, deliberately keep ordinary merge semantics.
- **A compaction record and the event after it are one unit.** `compaction/summary` and `compaction/prune` name a range and price it; the *next* surface event replaces that range. Nothing may be appended between the two. It is not tidiness: it is what lets a projection price a replacement with one running total and one pending claim instead of a price per message, so a checkpoint stays bounded. `crates/turn/src/compaction.rs` produces the pair and `crates/turn/src/projections.rs` consumes it; break the adjacency and the totals drift silently.

- **Compaction lives in the derivation, never in the file.** The journal is append-only, so nothing is deleted to shrink a conversation - `compaction::surface` changes how history is *derived*, which is why a replay reproduces a compacted session. Anything that reads model history must go through `derive_messages`; a second reader that folds surface events itself will disagree with the engine the first time a session compacts.

- **A sandbox is proven by being denied, never by being asserted.** `crates/sandbox` restricts a real thread or a real child and then performs the operation, because a case that inspected a policy object would pass just as happily against a backend that never made a syscall. Two traps are already paid for: `tempfile::tempdir()` lands under `$TMPDIR`, which `workspace-write` grants on purpose, so "outside the workspace" needs a directory outside every grant; and the child's half between `fork` and `exec` must stay allocation-free, which is why the Landlock syscalls are made by hand rather than through the crate. `ARCHITECTURE.md` §4.10 is the description.
- **Leaving the process is `crates/exec`, and the switch has to be shared.** Every child is spawned as its own process-group leader and killed with a SIGTERM-to-SIGKILL ladder over that group; a tool that starts one reads the *turn's* `Interrupt`, handed in by the composition through `tetanus_turn::boot::boot_with`. `TurnEngine` mints its own only when nobody provides one, and `tetanus_engine` mints one per session on purpose - a switch shared across sessions would let an interrupt in one stop another. `ARCHITECTURE.md` §4.9 is the description.
- **A tool call is recorded before it runs, and a terminal journal is a credential store.** `Tool::recorded` is what the engine asks before appending, and it is asked in three places - `tool/call`, `assistant/message`, `assistant/chunk` - because the model said the argument too; a fix that covers only the first covers nothing. Failing closed here is *silence*: a redactor that panics withholds every argument, the opposite direction from `ToolMode`'s fail-closed, because a broken classifier costs concurrency and a broken redactor costs a credential. Behind the flag is one backstop and no more: a terminal whose last output line asked for a password withholds what is typed into it (`looks_like_a_password_prompt`, `sudo`'s mechanism for `sudo`'s reason). It composes with the flag by union, never override. `ECHO`-off and the `[wait: stdin_read]` sequence are both measured dead here - readline and `stty -echo` pin the first to a constant, and the second is the *ordinary* settle reason for every finished command - so do not reach for either.
- **Two persistent shell families, and they are not redundant.** `shell_*` (`crates/exec/src/session.rs`) is a shell reading a pipe: cheap, exact through per-command nonce markers, and ended whole by an interrupt because a pipe has nothing to interrupt. `terminal_*` (`crates/exec/src/terminal.rs`) is a shell on a pty: it runs what needs a terminal, and an interrupt costs the command rather than the session. A terminal send settles on the shell's own OSC 133 prompt marker, which is why it can report an exit status at all; silence and the deadline are fallbacks, and a send that settled on one of those left a command running whose prompt can settle the *next* send. Anything that changes when a send returns changes `wait_for_readiness` and the wait reasons together.
- **Two shapes of child, one seam each.** A command you wait for is `crates/exec/src/proc.rs`; a peer you talk to over pipes is `crates/exec/src/piped.rs`, and `crates/mcp` starts its servers through it. Do not spawn a child anywhere else: the seams give every child its own process group and end the group, which is the only reason a server's helpers die with the server. Output past a capture bound is kept whole by the *producer* (`Tail` opens a spill writer on the first overflow), because anything above the seam only ever sees a result whose beginning is already gone.
- **A process group is not a terminal session.** Job control puts every job an interactive shell starts in a group of its own, so `killpg` on the leader misses `sleep 60 &`. `crates/exec/src/pty.rs` sweeps by session id through `/proc` for that reason; a group kill alone is how a harness leaves a `sleep` behind for an hour.
- **The offline mock's chunk count is load-bearing.** `crates/turn/src/llm/mock.rs` streams three text pieces and one tool call per first step whichever tool it picks (`!` in the prompt asks for `shell`, anything else echoes), because `MOCK_TURN_FLOW` asserts the whole event sequence by equality. Change the pieces and the conformance constant changes with it, in the same commit.
- **Outside-world failures are failed tool calls, never turn failures.** `crates/mcp` and `crates/web` both carry a class or code on the failed result (`McpFault::class`, `WebFault::code`), which is what the model reads and what a journal is searched by. The seams are what makes them testable offline: an MCP server is a `Link` (`crates/mcp/src/link.rs`) and every HTTP request is an `HttpTransport` (`crates/web/src/http.rs`), so policy lives above the socket and no case opens one. Keep new outside-world code on that side of the line. `ARCHITECTURE.md` §4.11 is the description.
- **`crates/mcp` ships a real MCP server for its own suite.** `src/bin/fixture.rs` is behind the `fixture` feature, enabled for the test profile only by the crate's self dev-dependency in `crates/mcp/Cargo.toml`; that is what makes `env!("CARGO_BIN_EXE_tetanus-mcp-fixture")` resolve in tests while a published build ships no test double. Protocol cases use a channel pair (`memory::pair`) and process cases use the fixture - do not merge the two files.
- **A preset is resolved once, at `session.create`, and lives in the session header.** `crates/engine/src/preset.rs` reads the roster; the id lands in `SessionHeader::preset`, a fork inherits it, and a later document edit never moves a composed session. A preset's tool subset is taken against the registry *that session* will run on, so it composes with `EngineConfig::session_tools` rather than replacing it. TC-PORT-PRESET-5 is the case that pins the first half; `ARCHITECTURE.md` §4.12 is the description.
- **A tool crate is not offered by the binary until it is a line in `crates/toolset`.** `sources()` is the whole registration surface: one named source per crate, drained through `Source::registered` so no tool crate needs an accessor. The binary composes it for both the catalogue and each session's registry, which is why `tetanus tools` and what a turn dispatches cannot drift. `crates/engine` deliberately is *not* a call site - it has no session and would gain a dependency on every tool crate - so it keeps the `builtin` source's tools as its offline minimum, held there by TC-TOOLSET-2. A green workspace proves nothing here: every tool crate tests its own tools, and only `crates/cli/tests/toolset.rs` execs the binary and sees what it actually offers.
- **TC-ENG-4 and TC-RPC-12 belong to whichever call is reserved *now*.** Contract section 4.2's `Reserved` status is served by a default trait body on `Engine`; those two cases assert that a reserved call answers `NotImplemented`, is routed rather than unknown, and is not advertised. Serving a call *moves* them to the next reserved call rather than retiring them, and the RPC routing arm is added by hand, so the arm that gets forgotten is the one no case names.
