deepseek-harness → Rust

What a rewrite can and cannot be, and the one real decision. Grounded in the actual clone (docs/architecture.md, API-gateway spec, package tree) — 2026-08-18.

What dsh actually is

568KTypeScript lines
~50workspace packages
0.1.0-rc.7breaking changes expected
MITlicense — rewrite is clean
100%plugins — even the agent loop

Its identity is Cordis: every part (model adapter, tools, session log, agent loop) is a hot-swappable plugin with reversible registrations, composed at boot from profiles/bundles/patch overlays. The web API is generated from @Remote decorators — not a hand-written, stable protocol.

The part worth stealing — the turn flow — is cleanly documented:

turn/start→claim input→prompt + schemas→agent/pre-step→llm/stream→tool pipeline→step/end→turn-stopping

The two roads

Option 1 — Rust host behind their web UI

~25–40K linesUI freeprotocol risk high
  • Keep their polished web bundle frontend; demo-able early.
  • Rebuild in Rust: Connection RPC framing, /api route, the generated Remote surface, Typert identity lookups, session-event stream.
  • Cost: the UI drags server scope far past the core loop — goals, plans, todos, skills, session-query…
  • Risk: married to an undocumented generated protocol at rc stage; every upstream bump can silently break the wire.
Chosen — full parity 2026-08-18

Option 2 — Clean Rust harness, everything dsh has but better

~25–35K lines at parity scopezero upstream couplingown protocol
  • Spec: their architecture / turn-flow / event docs; steal the best ideas (append-only log, capability seams, guarded tool pipeline).
  • Own: simple JSON-RPC/WS protocol; headless CLI first, thin web view later.
  • Phases: ① core turn engine → ② Cordis parity (live recompose, RAII effects, tool pipeline) → ③ better (WASM plugin host, conformance suite, perf proof).
  • Cost: no ready-made frontend; the WASM host is the priciest single line item — accepted.

dsh plugin lifecycle

mount→ctx.effect()→run→unload (unwind)→remount, session keeps running

Rust lifecycle

compose from config→topo-mount→run→unload (RAII unwind)→remount live, session keeps running

Why "better" is credible in Rust

single static binaryms cold bootregistry + events checked at compile timeno GC pauses mid-streamparallel dispatch without data racessandboxed plugins by default

The one honest residue

TS-style HMR of native core code→ms restart + session-log resume covers it

The one-line truth: nothing Cordis does is dropped. Composition, service registry, dep-driven load order, typed events, patch-layered config: kept and compile-time checked. Runtime mutability: kept via RAII effect handles, live subtree remount, and hot-swappable WASM plugins. The single residue is HMR of native core code, where a millisecond restart with session-log resume stands in — everything else is parity or better.

The decision — made

Locked by captain 2026-08-18: clean Rust harness at full dsh parity — "everything deepseek-harness has, but better." That retires Option 1 (living behind their generated protocol) and raises Option 2's bar: runtime mutability is in scope, not dropped — RAII effect handles, live subtree remount, and a WASM component host are core deliverables, not future maybes.

Phase ① coreHeadless CLI running one full documented turn: typed registry, event bus (4 modes), session log, one model adapter.
Phase ② parityLayered config + live recompose, RAII effect unwind, tool pipeline, remaining adapters, JSON-RPC/WS surface.
Phase ③ betterWASM plugin host (any-language, sandboxed), conformance suite against dsh's documented turn flow, perf proof: boot, tokens/s, memory.
