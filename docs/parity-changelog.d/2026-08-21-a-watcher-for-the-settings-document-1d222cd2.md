A watcher for the settings document (`crates/config/src/watch.rs`, TC-WATCH-1..9 plus -3b and -7b). `recompose` has been able to re-read a document since it was written and nothing ever called it, so a user who edited `settings.yaml` while the harness ran saw nothing happen until a restart. It polls, which is upstream's mechanism too - a `stabilityThreshold` is a poll - and it needs no dependency and behaves the same everywhere. A change is reported only once the file has stopped moving, because an editor that truncates and rewrites is momentarily an empty document and a watcher firing on the first event would hand a running harness the defaults. A bad edit is reported, refused by `recompose`, and the watcher keeps watching: one that stopped there would make a typo permanent until a restart, and the user's next action - fixing it - would appear to do nothing. The decision is a function of two observations rather than a thread, so a case writes a sequence of file states out literally instead of racing a filesystem's timestamp granularity. The mutation check found two blind spots and both are now cases: a settle count of three was never distinguished from two, and nothing called `Stamp::of` in a way that noticed it read a modification time at all.
