Removed a shared global from the host suite: `nothing_outside_the_frontend_is_served` wrote and deleted a fixed `$TMPDIR/secret.txt`, a name every process on the machine shares, and the case it belongs to is precisely the one asserting that a path outside the served root cannot be read. Two copies in different processes - which is what a full workspace run on a busy box produces - shared that one file, and a delete landing between another copy's symlink and its request leaves a dangling link, a dangling link is a miss, and a miss is the page: `HTTP/1.1 200` where the case demands 403. That is consistent with the one failure seen on 2026-08-23 rather than proven to be its cause; forty concurrent executions could not reproduce it, and the fix does not depend on the link being true, because a proven shared mutable path is a hazard whether or not it has bitten yet. The case now owns the directory the file lives in: one tempdir, the served root inside it, the secret beside it, so `..` still has something real to find and no name is shared with anything. The cleanup goes too - there is nothing to delete when the directory is yours. A sibling flagged by the same pattern, `crates/features/tests/view.rs:220`, was inspected and left alone: its fixture's path is a *file* inside its own tempdir, so `.parent()` is that tempdir rather than `$TMPDIR`, and nothing there is shared.
