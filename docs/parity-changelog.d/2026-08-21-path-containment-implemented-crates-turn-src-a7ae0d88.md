Path containment implemented (`crates/turn/src/fs.rs`) and ported (TC-PORT-FSC-1..12), the first of the `fs/*` and `sandbox/*` rows and the piece every later filesystem or shell tool has to stand on. It is containment and not a security boundary, and the module says so: the operations are this process's own and only the path is model-controlled, so canonicalize-then-contain is a complete answer to *this* surface, while isolating untrusted code stays a kernel problem nothing here solves. Resolution walks component by component rather than canonicalizing once, which is what makes two cases come out right - a path that does not exist yet is judged by the directory it would be created in, so a create is fenced before it happens, and a link reached after a missing segment is still followed rather than normalized away. The identity fallback recognises a root reached by another valid name, widening what counts as the root and never the fence. Writing the cases found one defect: a workspace rooted at a regular file was accepted. The mode layer over this fence, and the filesystem service and tools themselves, stay phase ②; the mutating tools are deliberately sequenced after the approval gate rather than before it.
