The executor a deployment's hooks run through (`crates/exec/src/hooks.rs`, TC-PORT-HOOK-1..6), closing the second half of the process row's piped-stdio clause - the half that named out-of-process hooks. `crates/hooks` had declared `HookExecutor` and deliberately implemented none, so the only one in the workspace was a recorder in its own suite: a deployment could configure a hook and nothing would ever run it. A hook now gets what every other child here gets, and the case that matters starts a watcher inside a hanging hook and asserts the watcher dies with it, because a hook runs inside a turn and one that leaks is a turn's worth of orphans per event. Two defaults differ from upstream on purpose: the environment is a list rather than a scrub, since nothing is inherited here and a denylist exposes every credential added after it was written - the case puts a secret in this process and watches it not arrive - and the timeout ceiling is the hook protocol's ten minutes rather than the shell tool's, because clamping a configured hook to a model command's budget would shorten it silently. The cases drive `run_hook` rather than the executor alone: what has to be true is not that a command ran but that the protocol reads the result as a hook, so a `2` blocks with its reason and a hook that never ran blocks nothing and says why. The bridge - registering hooks against `PreToolUse` and the rest - stays with the `hooks/*` row, which waits on interception points in the turn engine; what changes for that row is that its bridge slice now constructs an executor instead of writing one.
