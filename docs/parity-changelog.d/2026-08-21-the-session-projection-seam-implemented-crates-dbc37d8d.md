The session-projection seam implemented (`crates/session/src/projection.rs`) and ported (TC-PORT-PROJ-1..12), which is the phase ② item two other rows were explicitly blocked on. A unit contributes mathematics and nothing else - `init`, `apply`, `view` - while the registry owns the driving and the watermark, and that split is what lets a checkpoint exist: a value is reproducible from the log alone, so a stored one is only ever a shortcut. The two rules that make it safe are the ones the mutation check attacks: a row whose `state_version` is not this unit's is discarded rather than folded forward, because forward-applying a state that means something else turns one bad checkpoint into a permanently wrong value no new event corrects; and a row claiming events the log in hand does not have is discarded too, because it describes a history this caller cannot show and folding the tail onto it would splice two of them. State is JSON so a row can actually be persisted, and TC-PORT-PROJ-12 serializes one rather than taking the precondition on trust. The usage, pressure and breakdown units are the next slice; nothing registers a projection yet.
