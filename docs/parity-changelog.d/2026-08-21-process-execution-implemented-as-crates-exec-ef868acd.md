Process execution implemented as `crates/exec` and ported (TC-PORT-PROC-1..18, TC-PORT-SHELL-1..19, TC-PORT-TERM-1..14, TC-CLI-SHELL-1..3), taking the `shell/*`, `terminal/*`, `subprocess/*` row from one unregistered primitive to a seam a model can actually call. The termination gap the old row stated is closed the only way it could be: every child leads its own process group, and a kill is a SIGTERM-to-SIGKILL ladder over that group, so grandchildren die with their parent and a command that ignores SIGTERM still ends. Writing the cases found a second hazard nobody had named - a background process inherits the output pipe, so a leader that exits does not close the stream and a reader waiting for end-of-file waits for the orphan; the group is now swept and the caller is told it had to be, which is the difference between a turn that returns and one that hangs for the length of a `sleep 30`. Two backends sit behind one trait so Windows is a backend that is absent rather than a platform the seam cannot express, and a missing binary refuses loudly instead of falling back to another shell, because a bash script run under dash fails later, elsewhere, with a message about syntax. Persistent shells keep the working directory and exported variables between tool calls, bounded by a per-command nonce marker rather than by prompt detection; where upstream resets a dead shell and prints a notice, this keeps the notice and drops the reset, because a silent restart hands the model a shell in a state it did not create while the transcript says everything succeeded. The interrupt needed one composition change to be true rather than nearly true: `boot_with` lets a composition supply the turn's stop switch, the shell tools hold it, and the engine mints one per session - a switch shared across sessions would let an interrupt in one stop another. Moving the seam out of `crates/turn` also exposed a defect in the code it moved: a capture cut mid-character dropped one byte of a partial character and rendered the rest, and the old case could not see it because `printf '\u00e9'` is not POSIX and the shell behind `/bin/sh` printed the escape literally - a multi-byte case that had been running on ASCII. A PTY and the terminal tools that need one, background jobs, and spill files stay out, named in `docs/parity-updates/shell-process-execution.md` with the reason.
