A real pseudo-terminal (`crates/exec/src/pty.rs`, TC-PORT-PTY-1..8), which the previous sweep had named as the blocker for everything left in the terminal row. Four things it owns because none can be built on the others: allocation, where the child `setsid`s and takes the slave as its controlling terminal - without that second step it has a tty on its descriptors and no session to signal, which is the half-working state worth avoiding; size, set at allocation so nothing starts up believing it has the 0x0 screen an unconfigured pty reports, and resizable afterwards the way a terminal emulator does; signal delivery to the foreground process group, because `^C` on a terminal goes to whichever group owns the terminal and a harness that signalled the session leader would kill the shell every time the model meant to interrupt a command; and a read loop that drains continuously rather than on demand, since the kernel's pty buffer blocks a child that outruns its reader and the only way to lose bytes there is to stop reading. Past our own bound the beginning is dropped and the loss is reported, never silently shortening the transcript. The bounded buffer is factored out of `session.rs` into `transcript.rs`, because a pipe-backed shell and a terminal-backed one have the same hazard and should not have two answers. Three defects found while writing it, all in this slice's own code: `allocate` called `CString::from_raw` on a stack buffer, which would have freed memory nothing allocated; `wait` returned at process exit while the drain was still running, so a caller reading the transcript immediately after would intermittently miss the last thing the program said, and it now waits for the terminal to close with `wait_for_exit` kept for callers that mean only the process; and the signal case first asserted that a shell carries on through an interrupted command list, which `bash` does not do - it abandons the list when a foreground command dies of `SIGINT` - so the case now drives the session the way a terminal tool would, starting a command, signalling its group, then sending another command and watching the shell answer. The tools over the layer - viewport, scrollback paging, an owner-scoped registry - are the next slice and the row still carries them.
