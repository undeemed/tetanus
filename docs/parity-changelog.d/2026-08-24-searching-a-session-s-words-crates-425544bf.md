Searching a session's words (`crates/query/src/search.rs`, TC-PORT-QUERY-20..31), closing the full-text clause of the `session/*`, `session-query/*` row. The `text` filter clause is a substring test, which is right for a filter and wrong for a search box where a person types two words and expects an event about both; this is the second thing, with any-of and all-of, the ordinary filter composing into it, a bounded snippet and a cursor. The decision it is really about is the compaction surface. tetanus deletes nothing to shrink a conversation - `compaction::surface` changes how history is derived - so a long session holds text that is on the log and that the model has lost, and a search returning it unlabelled would show a person a sentence and imply the model can still see it. Upstream labels every hit for the same reason. What this crate will not do is derive that label: `AGENTS.md` requires one reader of model history, and the two ways to get it here were both wrong - a second fold is the disagreement that rule exists to prevent, and appears only on compacted sessions, which is to say only on the sessions long enough to be worth searching; while depending on `tetanus-turn` would drag an HTTP client and a TLS stack into a crate whose virtue is that it opens nothing. So the surface is an input, `Journal::with_surface` takes the seqs the caller's own fold selected, and a caller who supplies none gets `Unknown` rather than a `Current` nobody checked - the two are distinct because "we checked" and "we did not" are different facts. TC-PORT-QUERY-24 pins it structurally: it passes only while the surface is an input. No ranking, because a scan has no relevance number and inventing one would be a model no caller could tune; order is by seq, which is a fact. A cursor carries a fingerprint of its query's shape and is refused against another, because paging one search with another's cursor lines the seqs up and yields a plausible wrong page. The slice found one defect in itself: "are there more" counted events before the cursor rather than matches before it, which TC-PORT-QUERY-25 could not see because every event in its log was a hit; TC-PORT-QUERY-31 puts the non-matching events first, where the counts diverge, and the bug drops the last match. The first draft of that case put its fillers after the matches and passed against the bug it was written for, which is recorded because a case that cannot fail is worse than no case.
