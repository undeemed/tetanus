The `core/*` and `hooks/*` gap clauses swept against the code so each names precisely what is missing and why, rather than naming a feature. A clause that is only a noun - "scoped stores", "fiber disposal" - is a blank row wearing a label: it cannot be picked up, argued with, or closed, and it hides whether anything still blocks it. Two findings came out of the sweep and both change what the rows say. **The hooks bridges are no longer blocked on missing interception points.** That clause had been true when written and is now false: `PreToolUse` maps onto `tools/pre-execute`, whose output *is* the call that runs, so `updated_input` has somewhere to land; `PostToolUse` onto `tools/post-execute`, whose decision now carries contexts; `Stop` onto `agent/turn-stopping`, which already takes a veto; `UserPromptSubmit` onto the first `agent/pre-step`. What is actually left is a deny path and an owner for configuration discovery plus the executor binding. **A `PreToolUse` deny has nowhere to go, and it is the same dependency as the tool-permissions clause.** `tools/pre-execute` answers a `ToolCall` and cannot refuse one, and the gate after it fires only when `ToolRegistry::permission` already returns `Ask` - so a hook forbidding a call the registry marks `Allow` would be consulted and then ignored, which is worse than not consulting it, because a deployment would believe the hook was enforcing something. Both rows now name that single dependency: every gated call routed through the approval seam rather than only the ones a registry pre-declares. The remaining clauses each carry their reason - scoped stores and scoped prompt layers wait on a plugin context to scope to, which is the phase ③ host; cancellation inside a step is a contract question about what a half-read stream writes to the journal before it is a code one; a sticky cut-off step waits on the `next-turn` queue; `cwd` waits on a session having a working directory rather than on anything about the journal; runtime-context providers need a provider list the assembly walks, which is a change to `system-prompt/assemble` and therefore its own contract slice.
