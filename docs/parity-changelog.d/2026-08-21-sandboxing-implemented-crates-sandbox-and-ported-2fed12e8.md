Sandboxing implemented (`crates/sandbox`) and ported (TC-PORT-SANDBOX-1..19), opening the `sandbox/*` row from "None". The policy is upstream's three modes as one value resolved at a boundary and handed down whole, with the writable-root derivation in one place for upstream's own reason: two layers deriving it separately is how "the write tool cannot write /tmp but bash can" happens. Two things upstream leaves to its backends are said in the policy here - a network decision, because Landlock governs TCP from ABI 4 and a deployment wanting an offline build has nowhere else to say so, and whether partial enforcement is acceptable, because deciding that per backend is how a host silently gets less confinement than was asked for. The Linux backend is Landlock with the syscalls made by hand, and the reason is the fork/exec split: the ruleset is built in the parent where allocating is safe, and the child's half between `fork` and `exec` is three allocation-free system calls, because after a fork in a threaded process a child that allocates can deadlock on a lock another thread held. Deny-by-default is the ABI's own shape - the handled set is every right the kernel knows - which is what makes create, remove and rename governed rather than only write. Every confinement case restricts a real thread or a real child and then performs the operation, so a backend that never made a syscall would fail all twelve; the host here speaks ABI 8. Writing them found two things worth recording: `tempfile::tempdir()` lands under `TMPDIR`, which `workspace-write` grants on purpose, so the first two "denied outside the workspace" cases were writing into a granted root and failing correctly against a backend doing exactly what it promised - the fixture now picks a directory outside every grant and asserts that it is one; and the persistent shell was not confined at all, because the call that would have done it was written and never wired in, with a dead-code warning as the only evidence. Windows and macOS get a refusal that names the upstream backend a port would restate, never a no-op that reports success: upstream's ACL family is ~1500 lines across FFI, token, ACL and runner, and nothing in a workspace without a Windows CI host can prove any of it. The filesystem half is a named follow-up rather than a guess - `Policy` and `landlock::confine_current_thread` are the two pieces it needs, both written - and so is the approved-escalation retry, which belongs with `tetanus_turn::approval` rather than inside the sandbox crate.
