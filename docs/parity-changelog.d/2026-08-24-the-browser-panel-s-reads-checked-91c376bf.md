The browser panel's reads checked against the contract that publishes them (`crates/protocol/tests/panel_fields.rs`, TC-PANEL-FIELD-1 and -2). The presentation lane had written down a risk it cannot defend against from its own side - a field the page reads that is later renamed fails silently, drawing an empty panel rather than a build error - because JavaScript has no build to break. Rust has one, so the check sits where the rename is made: the case scans `web/app/*.js` for every `data.<field>` and asserts the contract publishes that name, which fails the engine's build the day somebody renames a field a panel draws. A mutation confirms it bites, and the second case exists because of a defect in the first cut of the first: a scan matching only lowercase truncated `data.handlerId` to `handler` and reported four fields as unpublished when all four were fragments of names the contract does name. A wrong probe does not fail quietly - it accuses the other side with a specific, plausible list - so the scan is now pinned by a case of its own.
