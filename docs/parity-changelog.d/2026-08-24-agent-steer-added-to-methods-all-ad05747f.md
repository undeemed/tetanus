`agent.steer` added to `methods::ALL`, and the hole that let it go missing closed (TC-PORT-API-3). The call was declared, routed, capability-named, and listed in `docs/interface-contract.md` section 4.2 as `Reserved` - and absent from the constant, so every consumer that iterates `ALL` to ask what this contract defines silently skipped it. This is a defect fix rather than a contract change: the document already specified the call, the crate disagreed with the document, and bringing the crate into line changes nothing about the contract, so section 8 gains no row and no shared doc is edited. The case is the substantive half. The original pinned the omission so a fix could not go unnoticed, which is a case with a lifespan; replacing it with "`agent.steer` is in `ALL`" would have had the same hole one level down, since it names one method while the defect class is any method drifting between the document and the constant. It now parses section 4.2's table out of the document and asserts set equality with `method::ALL` in both directions, which closes what the constant's own doc comment calls the single mistake it cannot catch - "adding a constant above and not adding it here... which is why the two sit together". Sitting together is a convention, and the convention is what this walked through. Parsing a specification inside a test is unusual and deliberate: the document and the crate are one contract, the document says so in words, and nothing was holding them to it. Both directions were mutation-checked - removing the constant entry fails it, and adding a constant with no documented row fails it too, along with the descriptor completeness case.
