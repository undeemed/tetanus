The mirror of the durable-type diff (`crates/host/tests/web_app.rs`, TC-WEB-11): the browser panel names no event the engine cannot produce. It guards a failure that leaves no trace - a mistyped type in a `case` or a table key never matches, so the handler simply never fires, the event falls to the raw path, and the page looks exactly like one the engine never told about it. Nothing throws and nothing logs; the only way to notice is to know what the transcript should have said. The rule is judged per family, which is what makes it precise rather than noisy: a name whose family the engine uses must be one the engine can actually produce, while a slash string from another vocabulary - the media type `application/json` sitting in a fetch header - is not an event name and is not treated as one. The vocabulary it checks against is topics plus the method and notification names the protocol crates declare, because the page handles `agent/status` and `ui/ask\', which are a push and a server-to-client request rather than journal entries, and a rule built on topics alone would call two correct handlers dead code. The page is clean today; the case is for the next rename.
