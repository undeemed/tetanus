A screen for the programs that draw (`crates/exec/src/screen.rs`, TC-PORT-SCREEN-1..7, TC-PORT-TERM-45), closing the row's own words: the sanitizer strips escapes and keeps no screen, so `htop` and `vim` were runnable here and not readable. Two models of one stream are kept because neither derives from the other - a printing program's transcript is what it said, and a drawing program's transcript is every frame concatenated with nothing marking which forty lines are still true. `terminal_read` picks by the one reliable signal a terminal carries: a program on the alternate screen has announced that it draws. Colour and attributes are deliberately not modelled, since a model reads text and an attribute model would double the file to record something nothing renders. Pointing the cases at the real `vim` and the real `htop` rather than at `printf` fixtures found two defects invisible to every sequence an author would have typed: terminal sessions advertised `TERM=dumb`, which tells a program there is no screen - so the very family this layer exists for was refusing to draw - and a session had no `HOME` or `PATH`, which is right for a one-shot command and wrong for an interactive program, and which made `vim` paint its status line and stop. The second read as a hole in the screen model for an hour; `TerminalConfig::passed` fixes it in the shape this lane already uses for hooks, a list of names that pass rather than a denylist of names that do not.
