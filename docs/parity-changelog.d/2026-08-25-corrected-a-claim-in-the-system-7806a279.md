Corrected a claim in the system-prompt port row that its own neighbour had contradicted for some time: it said runtime-context providers have no surface, while `crates/turn/src/context.rs` has served contract section 4.4.8 since it landed, and the same row's next clause reasons about a non-finite order being unrepresentable in an `i32` - which is the ordering that implementation uses. The correction is not just that they exist but that they are deliberately NOT a prompt layer: 4.4.8 makes a runtime context a user message carried after the retained history, so that a sentence changing every turn cannot invalidate the cached prompt prefix, and a reader who took this row at its word would have gone looking for a layer that should not be built. This is the fourth stale claim found in `parity.md` in two days and the third created not by anyone writing something wrong but by another lane landing work that silently falsified a sentence elsewhere in the document. The row is what people read before deciding what to build, so each of these is an invitation to build something twice - one such duplicate was already written and closed. Nothing here catches that decay except a deliberate re-probe against the tree, which is worth knowing before anyone relies on this document being self-maintaining.
