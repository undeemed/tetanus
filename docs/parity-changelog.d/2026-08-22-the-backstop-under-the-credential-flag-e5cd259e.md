The backstop under the credential flag (`looks_like_a_password_prompt`, TC-TOOL-RECORD-5, TC-PORT-TERM-43), decided by the captain from a scout report and built after the flag itself. The argument for it is that a caller flag fails open exactly where it matters - published measurement shows agents follow optional-flag policy rules inconsistently across repeated trials - so the flag is unioned with a runtime rule rather than shipped as a control. The mechanism is `sudo`'s, and the choice is evidence rather than taste: `sudo` had the terminal's `ECHO` flag available, says so in the first line of its own documentation for the feature, and built a regex over the program's output instead; this crate measured the same conclusion twice, since readline holds echo off at its own prompt and `backend.rs`'s `stty -echo` pins it off for the whole session. One narrowing from `sudo`: the match is on the last non-empty line rather than anywhere in the output, because a prompt is by definition the last thing written before a program waits, and `sudo`'s own default arms on a `grep` hit for the word - a false positive it accepts and has no published rate for. The rule lives in the engine and the evidence stays with the terminal: at record time the engine cannot know which argument names a session, and guessing would put tool semantics back where `Tool::recorded` exists to keep them out. Union, never override, per contract §4.3 - which is also the section that specifies the sentinel, correcting the §4.6 citation the original note carried.
