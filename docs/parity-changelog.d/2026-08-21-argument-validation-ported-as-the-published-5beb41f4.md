Argument validation ported as the published helper upstream actually has (`crates/turn/src/schema.rs`, TC-PORT-SCHEMA-1..10 plus a totality guard). Until now a tool's declared schema meant nothing after the model read it: every tool body either wrote its own defensive parsing or trusted a value the model invented. The slice was nearly shipped as a dispatch gate, and backing that out is the finding worth recording: upstream exports `validateArgs` for tool authors and its agent loop only parses, which is why its own `tool JSON parse` case asserts that a call whose arguments are not JSON still reaches its tool. Gating dispatch failed TC-PORT-ARGS-3, the faithful port of that case - so the gate would have been an invention contradicting a port rather than completing one. TC-PORT-SCHEMA-12 now states the gap deliberately instead of leaving it as an omission, and a hard gate stays a behaviour change that needs a contract clause first. The supported vocabulary is exactly upstream's, and an unrecognised keyword constrains nothing rather than being refused, so a tool using something this validator has not learned is never made to look wrong.
