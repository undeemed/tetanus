The enumeration half of listing a parent's children ported (`crates/subagent/src/children.rs`, TC-SUB-KIDS-1..14), and with it the engine slice that serves contract section 4.4.9 - `spawned_by` and `depth` on `session/start`, which the contract had explicitly left for a later engine slice to write. The field shape is the whole lesson of the slice. This started as one `origin` field with a kind beside it (`fork` or `subagent`), which reads as sufficient and is not: the contract had already ruled it out, for the case that breaks it. A fork of a subagent's journal is *both* - it inherits the `spawned_by` of the work it copies while recording its own `parent_session` - so a single origin field either classifies it as a fork and loses it from its spawner's listing, or classifies it as a subagent and loses the copy lineage. Two fields answer the two questions lineage exists for: what else came out of this conversation, and why does this session exist. Delegation is therefore exactly the `spawned_by` edge and parentage is never reported as it. Traversal is a separate question and crosses both edges, so an agent started from a fork of this conversation is still discovered while the fork itself is not reported - a walk following the delegation edge alone would stop at the fork and silently lose every running agent below it. Ordering is oldest first with the id breaking the tie, because enumeration order is whatever the directory returned and a listing read twice must not reshuffle itself; creation time needs no header field, being the `session/start` event's own timestamp. Every walk is iterative and bounded by a visited set that starts holding the root, because the corpus is files in a directory anyone can edit: a cycle, a link to a session that is not there, and a chain deeper than a call stack are all reachable without anything in this process going wrong, and a parent that hung - or aborted - while listing what it had delegated is the worst available answer. A fork inherits `spawned_by` and `depth` unchanged and writes its own `parent_session` and `fork_seq`, which is section 4.4.9's rule and not a new one. `depth` is `u32` in the engine header to match the width `crates/protocol` parses the same line at. Three cases go beyond upstream: the self-parent cycle an off-by-one in a spawner produces, liveness carried through rather than inferred since it is not a fact of a journal, and the persisted `depth` told apart from the walk's distance - a distinction upstream has no counterpart for because it has no separate spawn edge. Deliberately not ported: upstream's row materialization, which resolves each child's mode and label from its descriptor through the projection registry and diagnoses a settled child whose descriptor cannot be read - that needs the projection registry joined to persistence inspection, `crates/subagent/src/descriptor.rs` already carries the record it reads, and nothing here changes when it lands. `cwd`, the third origin fact, is still a gap: it needs a session to have a working directory.
