The WebSocket carrier authenticates (`crates/rpc/src/auth.rs`, TC-WSAUTH-1..8), enforcing contract section 4.1.2. Until now `websocket::serve` accepted any TCP connection and handed it the whole `Engine` - turns that run tools and spend money, every journal in the server's directory, the resolved configuration - with no token, no origin check and no per-call authorization. Two attacks, neither exotic: a server bound off-box is reachable by anyone who can route to it, which the standing rule makes the expected deployment; and the same-origin policy does not restrict WebSocket connections, so a page the user merely visits can open `ws://127.0.0.1:<port>` and drive the agent. `Origin` is therefore checked in every posture, because "local" and "trusted" stopped being the same thing the moment a browser could be the local peer. Default deny: the weakest posture offered still refuses every off-box peer and every browser origin, and there is no constructor that admits everyone. Refusal happens before the upgrade, which is why the contract adds no error code - an unauthenticated peer never reaches the JSON-RPC layer. A token travels in `Sec-WebSocket-Protocol` or the URL because a browser's WebSocket API cannot set headers, and the subprotocol wins when both are sent, since a URL reaches more logs. Upstream is unauthenticated and this is a deliberate difference, recorded in section 5.
