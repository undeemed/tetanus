The agent inbox ported (`crates/turn/src/inbox.rs`, TC-INBOX-1..16): the two queues that hold input arriving while the loop is busy, and the durable splices they are folded from. A person types while the agent is working; that message cannot join the request in flight and must not be dropped, so it waits for a boundary that can carry it. Two queues rather than one because the boundaries differ - `next-turn` holds prompts each wanting a turn of their own, `next-step` holds input joining the turn already running, and merging them would either run steering as a fresh turn or bury a prompt inside one. A turn boundary claims all of `next-step` and exactly one queued prompt: a person who queued three questions asked three questions. Two rules carry the durability. The journal commits before the projection moves, so a journal that refuses the append leaves the queues exactly as they were - serving a message from memory that no restart remembers is worse than never accepting it, because the person watched it join the queue and has no reason to type it again. And what is recorded is the *normalized* splice, never what the caller said: a record holding `-1` would be re-derived at replay against a list of a different length and reconstruct a different queue from the same journal. A claim is a pure deletion while a cancel records `canceled`, so a reader can tell what a person withdrew from what the loop delivered. Identity is unique across both queues together, because two entries answering to one name make cancelling one of them a coin toss. Clearing cancels `next-step` before `next-turn`, so a crash between the two writes leaves the prompts - which still mean what they said - rather than steering aimed at a turn that may already have ended. Adaptations: upstream publishes notifications through a Cordis service and these are returned from the mutation, this workspace having no notification service and a private one being a second surface competing with the journal; and upstream's id lives on its `UserMessage` while `tetanus_turn::llm::Message` is the provider wire shape, so the id is on the pending entry instead. Upstream normalizes `NaN` and fractional coordinates because a JS number can be either; `i64` cannot, so the type enforces that rule and the surviving coordinate cases are ported. Six mutations, all caught, including the ordering one - moving the append after the projection fails the refused-journal case. The consumers are next: `tools/post-execute` has no additional-contexts channel yet, which is what the hook bridges and the repeat-tool guard both wait on.
