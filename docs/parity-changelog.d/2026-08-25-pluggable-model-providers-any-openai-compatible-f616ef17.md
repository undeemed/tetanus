Pluggable model providers: any OpenAI-compatible endpoint declared in the settings document (`crates/turn/src/llm/openai_compat.rs`, `crates/engine/src/providers.rs`, TC-OAI-1..5, TC-PROV-1..17, TC-CLI-PROV-1..7, TC-CLI-SERVE-9, TC-WEB-12..15). Before this, a provider was a variant of a clap enum: two routes, both compiled in, and `tetanus serve --frontend` advertised only the offline mock however the document was written, because the browser panel is drawn from `catalog.models` and the registry was composed by hand at one call site. Now a route is a block under `llm.providers.<name>` - the namespace the retry reader and the credential store already share - realized by the DeepSeek transport under a name a document wrote, because that adapter *is* the OpenAI-compatible wire and a second copy of it would drift where nobody has a live key to notice. The registry is composed once, in `EngineConfig::from_settings`, which is what makes `--adapter <name>`, `tetanus models` and the panel's picker agree by construction rather than by three lists kept in step; `EngineConfig::default()` still holds the mock alone, so every offline fixture is unchanged. The CLI's `deepseek` spelling survives as an alias for the `deepseek-official` route rather than as a unification, which would have rewritten journal fixtures across the conformance suite for no behaviour. Reading a block refuses what it cannot honour - a missing address, a missing credential reference, a name a built-in owns - and ignores what is not its own, because the credential store writes `api_key` into the same namespace and refusing an unrecognized key would make storing a credential a boot failure.
