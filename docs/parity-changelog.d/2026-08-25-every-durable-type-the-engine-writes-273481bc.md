Every durable type the engine writes is drawn by the browser panel or listed as not (`crates/host/tests/web_app.rs`, TC-WEB-10). This is the diff that found `question/asked` and `question/answered` sitting undrawn for weeks while `questions.js`'s own header claimed them, and then the whole `compaction/*` family; both were found by hand, and this runs the comparison in the suite. It reads the vocabulary two ways because the codebase declares it two ways - a constant inside a `mod topic` block, and a literal handed straight to `append` - and a rule that saw only one would report a blind spot as a clean bill. Method names are excluded by construction, since those live in `mod method`; a scan that swept them in would demand the page draw `tools/list`. Running it found six more: the four `workflow/*` types, which landed after the last pass and want one view between them, and `permission/preset` and `fs/mode`, which are the preset a person chose and the filesystem knob whose last value is the session's. All six are listed with their reasons rather than quietly drawn as raw JSON, and the list is asserted in both directions so it shrinks when the work is done. What the case cannot say is whether a type is drawn *well* - only that the page has an opinion about the whole vocabulary rather than an accidental subset, which is exactly how a type named in a file's own header went undrawn.
