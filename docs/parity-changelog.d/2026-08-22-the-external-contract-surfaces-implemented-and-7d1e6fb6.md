The external contract surfaces implemented and ported (`crates/query`, TC-PORT-QUERY-1..19; `crates/sdk`, TC-PORT-SDK-1..12 and TC-PORT-API-1..14; `crates/acp`, TC-PORT-ACP-1..24), closing the `acp/*`, `sdk/*`, `api/*` row's three named gaps and the query half of `session-query/*`. Reading a journal as data derives position rather than carrying it: contract section 4.3.1 puts `turn` and `step` on the structural events and on nothing else, so one forward pass works the boundaries out and hangs them on every event - adding the fields to the journal would be a wire change for something the order of the lines already implies. An absent clause and an empty one stay different questions, because a `Vec` that could not tell them apart turns a filter built from an empty user selection into "match everything", the most expensive possible wrong answer. The SDK is two layers for upstream's reason: a protocol client that enforces the handshake exactly as a carrier does, and an owned-run API over it that exists for one ordering bug - the subscription has to be open before the prompt or the first events are already gone, which a caller writes once and debugs for a week. The gateway is the request surface as data, because the codec's `match` over method names cannot be enumerated and so nothing could answer what calls exist and what arguments they take; writing it found that `method::ALL` omits `agent.steer`, which is declared, routed, capability-named and reserved, and TC-PORT-API-3 pins the omission so the owning lane's fix is noticed. ACP brings no second carrier - it is a `FrameHandler` on the stdio carrier `crates/rpc` already serves, since a second framing implementation is a second place for framing to be wrong - and the ACP session id is the engine's own, so an operator holding one can find its journal and no mapping table can fall out of step. Three deliberate departures: tool activity goes on the ACP wire, because §7.2 already fixes that the journal is the stream and withholding it would build the quieter second history that rule exists to reject; `max-steps` maps to `max_turn_requests` rather than `max_tokens`, since a client told the latter would shorten its prompt and be wrong about why; and a harness rejection is `end_turn` rather than `refusal`, which would put words in the model's mouth. The bridge's client half is a second process on purpose - the suite re-enters the test binary as an agent over real pipes - and it earned that immediately: `close` shut the write handle down while still owning it, so the child never reached end of file and every teardown quietly waited out the ten-second kill fallback before killing a process that would have left on its own. It passed either way; only the clock could tell, and TC-PORT-ACP-22 is now the clock. What stays open is named: image and audio prompts wait on the durable attachment store, ACP session load, fork and resume are unbuilt, and the permission channel is built and pinned on both sides but has no engine-side approval seam to be driven from, which is a contract change rather than a lane change.
