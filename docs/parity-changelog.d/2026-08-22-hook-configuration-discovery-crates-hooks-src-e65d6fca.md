Hook configuration discovery (`crates/hooks/src/discovery.rs`, TC-HOOK-DISC-1..11): the last piece between a bridged turn and a deployment that can switch hooks on. Everything else in the crate is handed its hooks; this reads them off disk. Three failures live here and a deployment does something different about each, so `LoadError` keeps them apart rather than flattening them into a string: the file is not there, the file is not JSON, or the file is JSON that does not describe hooks. An absent file is deliberately not an error - most deployments configure none, and making absence a failure would make every composition site ask first, with the forgotten check turning "no hooks" into a startup failure. A file that exists and will not read is the opposite case and is reported: somebody wrote it on purpose, and reading a typo as "no hooks configured" would silently drop every guard that deployment believed it had, which is the worst outcome available because they think they are protected and are not. Every message names the file, since a deployment may configure one per dialect and a message that does not say which sends somebody to edit the wrong one. The subtle rule is that `${CLAUDE_PROJECT_DIR}` is substituted into commands *and* exported to the hook process as `CLAUDE_PROJECT_DIR`, resolved once from one field so the two cannot disagree - a command rewritten against one directory while the process is told about another would launch a hook pointing at one tree and reading from a second. Exporting it at all is load-bearing: Claude Code always does, and unmodified hooks in the wild use it to find project-relative files, so the bridge dropping it would run those hooks *successfully* against the wrong directory, which is worse than not running them. An unset token is left verbatim rather than blanked, because `${CLAUDE_PLUGIN_ROOT}/x.sh` becoming `/x.sh` names a real and quite different path. A hook this harness will not run is named rather than dropped, so a startup log can explain why nothing fires. `conventional_path` spells the conventional candidate without going looking for it: a bridge that hunted a directory tree and picked up a file nobody pointed it at would be running programs nobody authorised. One gap closed along the way - the bridge was passing `env: None` to every hook run, so `CLAUDE_PROJECT_DIR` had no way to reach a hook even once discovery could resolve it. Four mutations, all caught.
