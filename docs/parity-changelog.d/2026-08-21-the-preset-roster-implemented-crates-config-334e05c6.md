The preset roster implemented (`crates/config/src/preset.rs`, TC-PRESET-1..10 plus -5b), opening the `preset/*` row. A preset is a directory holding an ordinary settings document, so a deployment that wants a cheap short-budget profile beside an expensive thorough one stops keeping two copies of one document. Roots are searched most-trusted first and the earlier one wins a duplicate, so a shipped preset cannot be silently replaced by a user directory of the same name - and the one that lost stays in the roster marked shadowed, because otherwise "my preset does nothing" has no answer anywhere. A candidate that is not a working preset is reported rather than skipped, since a preset that simply fails to appear gives its author nowhere to look; a directory that was never trying to be one, like `.git`, is skipped instead, and writing that case is what found that a leading dot passed the id rule. A root that cannot be read is a fault and not an empty root, which is the rule the session store and the key-value store already follow: absence and refusal are different facts, and answering "none" would serve a deployment a configuration it did not choose.
