`run_in_background` served for the one-shot `shell` tool, with the collection tool that makes it reachable (`crates/exec/src/background.rs`, TC-PORT-SHELL-22..28), closing the last buildable clause of the `shell/*`, `terminal/*`, `subprocess/*` row. The job store landed with no consumer and both rows named the same first one, so this is that consumer rather than a second store. Three things make it a background run rather than a slow call: the job is recorded before the process starts, so a crash between them leaves a queued job rather than an untracked child; the output goes to a spill artifact opened at the start rather than at a bound, because a command nobody is waiting for has no result to carry it; and the run is not handed the turn's interrupt, since a backgrounded suite is not the turn's command and sweeping it would make the argument mean 'until the user presses stop'. TC-PORT-SHELL-27 is that clause. The convention over the store is published as contract section 4.3.6 in its own PR ahead of this one, because it is a convention over the jobs row's type: the store keeps a producer's final output and explicitly not a stream, so the rendered result goes in `output` where that field intends and the unbounded stream goes to the artifact, whose path rides on `detail` as JSON. A live job's path is answered by the process running it, because `queue` and `start` take no detail - a limitation of the store found while writing this and stated in the clause rather than worked around. Collection is served from this row's own `shell_result` until `tool-jobs` exists, because a producer with no consumer is the defect this workspace has now shipped four times. A deployment with no store refuses the argument by name rather than running the command in the foreground, which would block the step the model tried not to block. One test-design bug is recorded: the first cut of TC-PORT-SHELL-25 asserted on the whole collection, whose status line quotes the command as its label, so 'the second line has not been printed yet' was read against text that contained the whole command - it now scopes the assertion to what was printed.
