The first automated cases over the browser panel (`crates/host/tests/web_app.rs`, TC-WEB-1..7). `web/app` had none anywhere in the tree, so every change to it - including the standing parity target - was defended by a person looking at it, which is how three defects lived there for weeks: `.row` defined twice so every conversation line lost its speaker column, `.said` defined by both stylesheets so every message drew in a proportional font inside a monospace row, and `.choice.dot` wearing one class from each file and staying correct only while the load order favoured it. All three are one fault - a stylesheet has one namespace and no compiler - and the case that generalises them is stated over the scripts rather than the stylesheets, because ownership lives there: `primitives.js` is the design system, and a second script putting one of its class names on a different element is the clash. Stated over the stylesheets it would have to refuse `.row > .disclose` too, which is the same shape and the opposite meaning - the page scoping a primitive on purpose. Everything asserted is structural and readable off the files as text: no browser, no DOM, no Node, which the CI job could not have run and which the project's own 'one self-contained binary' note argues against acquiring for this. What that leaves bare is rendering - whether a tool call draws the fold it should - and it is named in the module rather than left to be discovered. Each case was proved to fail against the defect it describes; the first draft of TC-WEB-1 passed against a restored `.said` collision, because a rule about bare selectors cannot see a bare rule in one file reaching into a scoped one in the other.
