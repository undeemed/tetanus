The settings leftovers served (`crates/config/src/schema.rs`, `write.rs`, `reload.rs`, TC-PORT-SET-5..12, TC-PORT-WRITE-1..9, TC-PORT-RELOAD-1..8) and the `core/*` row's scoped stores (`crates/core/src/scoped.rs`, TC-PORT-SCOPED-1..8). Three settings faults had one cause - nothing knew the shape of a key - so one declaration fixes all three: a scalar written where a section belongs was ignored, which let a user turn something off and change nothing with nothing saying so; a value of the wrong type reached whichever reader got to it first, mid-run; and a credential was hidden by the spelling of its key, which decides wrongly in both directions, publishing `llm.providers.x.auth` and hiding `deploy.token_count`. A key no namespace declares is still accepted, because a whitelist would make the schema a second register every plugin must join before its settings can be written. Writing the document back is a read-modify-write over the document's own nesting, atomic and owner-only with the mode set before any content goes in, refusing to write through a scalar or over a document it could not parse - starting from an empty one would turn a typo into the loss of every setting. The watcher and the re-read existed and nothing joined them, so an edit still did nothing until a restart; the joining piece is a step the caller drives rather than a thread, a refused edit leaves the running configuration standing and the watching continues, and the schema is applied at run time so a harness cannot be edited into a state it would have refused to start in. Scoped stores keep working state per scope with disposal on an `EffectHandle`; upstream's parent chain is deliberately absent, because an inheriting lookup is how a child acts on a belief its parent established.
