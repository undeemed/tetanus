A persistent shell now keeps the whole of a command's output when its scrollback drops part of it (`crates/exec/src/session.rs`, `transcript.rs`; TC-PORT-TERM-47), and the credential backstop learned the words the row's gap named - `passcode`, `pin`, `verification code`, `one-time code`, `otp` (TC-TOOL-RECORD-5, widened). The spill argument transferred from one-shot commands without change, but the implementation did not, and the difference is the part worth recording: the first attempt opened the artifact when the run loop *noticed* the bound had dropped something, which is always after the fact - the case asked for 3,000 lines and the file held the last 1,915. A bounded buffer forgets inside `push`, and that is the only moment the forgotten bytes still exist, so `Transcript` now hands them to a listener at the drop rather than at the notice, with the absolute position they started at; a session listens for exactly the length of one command, and a guard removes the handle however the command ends, because a command can also end by timeout, by interrupt or by its shell dying and a handle left installed would file the next command's output under this one's name. The rule generalises past this crate: if you drop bytes, hand them over at the drop. On the backstop, widening a word list is safe in one direction only - a rule can only add secrecy, never remove it - which is why the list is allowed to be generous, though `pin` being three letters pays for an edge check the longer words did not need, or `spinning up the container` would withhold whatever the model typed next. One process note: the first edit to that matcher silently did not apply, because the file had been reformatted since it was read and the search text no longer existed, and the build stayed green over an unchanged function - only the case caught it.
