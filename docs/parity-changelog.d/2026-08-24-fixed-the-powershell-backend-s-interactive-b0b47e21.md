Fixed the PowerShell backend's interactive invocation (`crates/exec/src/backend.rs`, TC-PORT-SHELL-21). The trait's `interactive()` defaults to the pipe invocation, which is honest for a backend with no separate interactive mode and wrong for this one: pwsh's session argv carries `-NonInteractive -Command -`, `-Command -` means "read the script from redirected standard input", and pwsh checks that standard input really is redirected - on a pseudo-terminal it is not, so the process prints its usage and exits 64 before a prompt exists. TC-PORT-TERM-32 asks for a `pwsh` terminal and accepts either answer a host can honestly give, a session or "this host has no pwsh", and got a third: `DiedStarting { backend: "pwsh", status: Exited { code: Some(64) } }`. It was invisible on every developer box here because no host in the fleet has a PowerShell, and red on every pull request because GitHub's `ubuntu-latest` runner ships one. Reproduced locally by putting a PowerShell 7.4.6 tarball on `PATH`, which failed the case identically. The fix is the backend's own: `PowerShell::interactive()` is `-NoLogo -NoProfile`, the REPL, which is what a terminal session wants and what pwsh runs when it is given neither `-Command` nor `-NonInteractive`. The test's expectation was left alone - a present-but-unusable backend is a defect in the invocation, not a third outcome a caller should learn to read. The new case asserts the argv rather than opening a session, because a case that can only fail on the one host that has a PowerShell is a case this fleet would not have run; it fails on every host with the fix reverted.
