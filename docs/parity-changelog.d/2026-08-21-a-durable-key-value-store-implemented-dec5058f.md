A durable key-value store implemented (`crates/core/src/storage.rs`) and ported (TC-PORT-STORE-J1..J13), opening the `storage/*` row. The session log answers what happened; this answers what a run worked out - a projection checkpoint, a computed title, a cache - each reproducible from the log and expensive enough to keep. Four rules carry it: tables are declared at open so a typo is a caller error rather than a table nobody reads; the file is replaced whole by an atomic rename after an fsync, with the directory fsynced behind it; memory is rolled back when a publish fails, so a caller that ignores the error still reads what a fresh open would read; and nothing is written until something is stored. Writing the mutation check found the gap worth recording: three mutations were caught immediately, but replacing the atomic rename with a copy passed every case in the suite - atomicity is the headline promise and nothing pinned it. TC-PORT-STORE-J13 now does, by inode identity and by a reader held open across a publish, which is the observable difference between swapping a file in and rewriting one underneath its readers. Nothing calls the store yet; persisting projection checkpoints is its first intended caller.
