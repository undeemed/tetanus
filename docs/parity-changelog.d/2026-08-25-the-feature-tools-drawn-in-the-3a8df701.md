The feature tools drawn in the browser panel (`web/app/tool-features.js`), against the renderers the trace panel already used. Seven tools this build offers had no view - `todo_write`, `update_goal`, `get_goal`, `exit_plan_mode`, `report_feedback`, `skill`, `tools` - so the page could show the task list under Tasks while the call that wrote it sat in the transcript as a JSON tree of eleven objects. The renderers are imported rather than rewritten, which is the point rather than a convenience: `todo_write`'s arguments are `todo/write`'s payload and `exit_plan_mode`'s argument is `plan/presented`'s, so a second reading of those shapes would be two places deciding what a task list looks like and would drift the first time one of them learned a new status. What is not shared is the wording, because a call and a record are different claims - one is what the model asked for, the other is what the session now holds. Two shapes close enough to merge and deliberately not merged: `get_goal`'s two absences differ by one word and only one of them is somebody's decision, and `report_feedback` is not drawn by the record renderer because that one carries an author and a call has none, so labelling it unattributed would say something false about a remark whose author is plainly the model. A result that does not parse is printed as the tool's own words - these tools serialise with a `{}` fallback, and assuming the shape would draw an empty task list for a serialisation failure, which reads as the model emptying the list.
