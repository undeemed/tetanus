Swept the `core/*` gap column against master and removed three clauses that had gone stale, two of which the same row's Today column already contradicted. Scoped stores were listed as waiting on the phase 3 WASM host for want of a scope to hang them on; `crates/core/src/scoped.rs` has served them for some time - keys per scope so one session cannot read another's, disposal as an `EffectHandle` so state goes when the scope goes - with eight cases behind it. `cwd` was listed as waiting on a session having a working directory; it is written at creation, inherited across a fork per section 4.4.9's rule, and covered in `session_origin.rs` and `fork.rs`. Runtime-context providers were listed as needing a provider list the assembly walks and therefore their own contract slice; `crates/turn/src/context.rs` serves section 4.4.8 with eleven cases, and the Today column did not mention it at all, so the row was understating what is built as well as overstating what is missing - that clause went stale between this sweep being written and being landed, which is the argument for re-probing a documentation change against the master it will actually land on rather than the one it was written against. A gap clause that contradicts its own row is worse than a blank one: a reader cannot tell which half is true, and the row is the document people consult before deciding what to build, so a stale clause is an invitation to build something twice - as nearly happened here, since a second implementation of 4.4.8 was written against exactly this row and closed as a duplicate. The scoped-prompt-layers clause survives on substance but was rewritten, because it justified itself by pointing at the scoped-stores clause that has now gone. Every remaining clause was probed against the code rather than read: the permission table, the `next-turn` queue half, cancellation inside a step, the sticky cut-off step and fiber disposal all still hold.
